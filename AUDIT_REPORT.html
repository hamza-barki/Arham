2. Admin Authentication & Fail-Closed Architecture

The system enforces defense-in-depth access controls using edge middleware, server-side session cookie verification, and role resolution:

  • Edge Middleware Guard (middleware.ts): Intercepts every incoming request targeting /admin/:path* and /api/admin/:path*. Inspects Supabase SSR HTTP cookies via @supabase/ssr. Unauthenticated requests to page routes are redirected with HTTP 307 to /login?redirect=...; API routes receive JSON 401 Unauthorized.
  • Fail-Closed Safety: In production (or when DEMO_MODE !== 'true'), if Supabase credentials are missing or unconfigured, the application halts with HTTP 503 Service Unavailable, preventing any unauthenticated or mock admin access.
  • Storefront Admin Button Visibility: The "Admin Console" link in desktop and mobile navigation bars (components/layout/Navbar.tsx) is wrapped with {isStaff && ...} and is never rendered to anonymous visitors or normal retail customers.
  • Server-Side Component Security: app/admin/layout.tsx exports export const dynamic = 'force-dynamic' and export const revalidate = 0, ensuring Next.js never statically prerenders admin pages or leaks admin dataset traces into client JS bundles.

5. Operations Dashboard Reconciliation

Metrics in app/actions/admin-dashboard.ts were refactored to compute authoritative numbers from PostgreSQL with explicit day boundaries:

  • Pakistan Standard Time (PKT) Boundary: startOfToday is computed as midnight in the Asia/Karachi (UTC+5) time zone.
  • Reconciled Revenue: Revenue is calculated as the sum of total_amount across all active, non-cancelled orders.
  • Return to Origin (RTO) Rate: Computed as returned_rto / (delivered + returned_rto) * 100. When no orders have reached final delivery or return status, the metric defaults to 0% with clear period labels.
  • Empty States: When 0 records exist for recent orders or low stock items, clean empty state placeholders are rendered.

9. Database Hardening Patch (User Action Required)

To finalize the database security hardening in live Supabase PostgreSQL, execute the SQL script in your Supabase SQL Editor:

Action Required: Open your Supabase Dashboard → SQL Editor → Copy and paste the contents of supabase/apply_security_hardening.sql → Click Run.

This script executes the following database-level controls:

  • Drops Permissive Anon Insert Policy: Removes "Customers and guests can insert orders" from public.orders and public.order_items, preventing direct client order injections.
  • Adds DB-Level Unique Constraints: Adds idempotency_key and confirmation_token unique columns to public.orders.
  • Deploys place_order_atomic RPC: Enforces server-side price validation, row-level locking (FOR UPDATE OF pv), and atomic inventory deduction with service_role restriction.
  • Revokes Public Execution: Explicitly runs REVOKE EXECUTE ... FROM PUBLIC, anon, authenticated on the atomic order function.
